# SOLARIS entitlements — Ed25519, server-authoritative (SOLA-34)

Status: **implemented and unit/integration-tested on the client and the pure
server core**. Independent security/licensing review (Riven) and release
behaviour verification (Naomi) are **required** before this is considered done;
Akira does not self-certify this path.

This document is the delivery report: root cause, files, before/after behaviour,
tests, limitations, rollback and security implications.

## 1. Root cause (verified, SOLA-2 P0-1)

| ID | Defect | Before |
| --- | --- | --- |
| P0-1a | Symmetric HMAC-SHA256 secret required to verify in the browser | Anyone who read the bundle could mint unlimited, eternal Pro keys |
| P0-1b | Production built with no `VITE_SOLARIS_LICENSE_SECRET` | `activate()` always returned `false`; a paying customer was refused |
| P0-1c | `loadStoredLicense` trusted attacker-controlled storage (JSON type-check only) | Editing `localStorage` granted Pro |
| P0-1d | Expiry was `Date.now()` on the customer's machine; no activation count, no revocation | Clock rollback extended a licence; revocation was impossible |

## 2. Target architecture (implemented)

- **Ed25519 (RFC 8032)** tokens, verified with a **public** key. The client
  holds no signing material. `src/licensing/token.ts`.
- **`kid` header** for rotation: a compromised key is removed from the ring /
  revoked server-side without shipping a new client.
- **Canonical, delimiter-safe encoding**: `base64url(header) "." base64url(payload) "." base64url(signature)`
  (JWS compact). The signature covers `header_b64 "." payload_b64`. The old
  format split the body on `-`, which broke any payload whose base64url
  contained `-`; dot-delimited base64url cannot collide.
- **Server-authoritative activation** (`src/licensing/server/activation.ts`):
  activation counting per subject, first-class revocation (per activation and
  per subject), absolute server-issued `grace_exp`.
- **Issuance only from a verified webhook** (`src/licensing/server/webhook.ts` +
  `server/http.ts`): raw-body HMAC-SHA256, timestamp window, replay protection.
  Settlement matching (`src/payments/confirm.ts`, reviewed under SOLA-6) runs
  only after the transport gate passes.
- **Non-exportable signing key**: issuance takes an injected signer
  (`issue.ts`); production uses a KMS/HSM. An env PKCS#8 fallback exists for
  self-host and is flagged as such.
- **Durable store interface**: `ActivationStore` with `MemoryActivationStore`
  (tests), `KvActivationStore` (Cloudflare KV / any get-put-list store).

## 3. Token format

```
base64url({"alg":"Ed25519","typ":"SOLARIS-LICENSE","kid":"sol-2026a","v":1})
.
base64url({"edition":"pro","sub":"order:P1001","iat":<ms>,"exp":<ms>,"grace_exp":<ms>})
.
base64url(<64-byte Ed25519 signature over "header_b64.payload_b64">)
```

- `exp` — paid-term end (server clock, absolute).
- `grace_exp` — absolute **server-issued** offline cutoff, signed into the
  token. A tampered client store cannot extend it.

### Public key ring

`src/licensing/keys.ts` ships **only** the public key for `sol-2026a`. The
matching private key is generated by `scripts/gen_license_keypair.mjs`, is never
committed, and is proposed to the operator as a Paperclip secret (`env.*`).
Rotate by adding a `kid` here and signing new tokens with the new key.

## 4. Behaviour matrix (outage / expiry / revocation)

| Situation | Client | Server | Result |
| --- | --- | --- | --- |
| Online, valid, under term | verifies token | `entitled:true` | Pro |
| Online, past term, under `grace_exp` | verifies token | `entitled:true,status:grace` | Pro (outage tolerance) |
| Online, past `grace_exp` | token fails locally | `entitled:false,status:expired` | Free |
| Online, revoked | — | `entitled:false,status:revoked` | Free (cache cleared) |
| Offline / backend down | verifies signed token | unreachable | **Pro until `grace_exp`** — never bricked |
| Offline, past `grace_exp` | token fails locally | unreachable | Free (revocation lag is bounded by design) |
| Tampered storage, token not signed by a ring key | local Ed25519 verify fails | — | Free |
| Forged token (attacker key) | local Ed25519 verify fails | `entitled:false` | Free |
| Activation ceiling reached | — | `entitled:false,status:activation_limit` | Free (cost control) |

The HTTP contract encodes this: **HTTP 200 + `{entitled:boolean}` is
authoritative; any non-2xx/network failure is an outage** and the client keeps
the signed, time-bounded entitlement.

## 7. Limitations

- Durable counting and revocation require the `SOLARIS_LICENSE_KV` binding. The
  in-memory fallback is per-isolate and does **not** guarantee counting/revocation
  across cold starts.
- The Cloudflare Pages Function adapters are thin and were not executed in the
  Workers runtime here (no local workerd); Naomi verifies release behaviour.
- `grace_exp` bounds offline revocation lag. This is intentional: the client runs
  on hardware the customer controls, so this is cost control, not DRM. No result
  here is described as unbreakable.
- The committed public key `sol-2026a` has no usable private key until the
  operator approves the secret proposal. Until then, self-host can issue with
  `--key` and a locally generated keypair.
- The webhook adapter expects a normalized `{subject, termDays?, graceDays?}`
  body; the PSP-specific body→subject mapping is a follow-up once the provider
  contract is fixed.

## 8. Rollback

Flag-free, one `git revert` of the SOLA-34 commit restores the previous
licensing behaviour. There is no migration: storage is a best-effort cache and
old-format keys already failed in production. No irreversible state.

## 9. Security implications

- Removing the symmetric secret closes offline forgery and the bundle-secret
  exposure (P0-1a). Verification material is public by design.
- Forged tokens are rejected locally **and** by a server round-trip (tested).
- Tampered `localStorage` grants nothing: entitlement is derived from signed
  claims, never from the stored record (tested).
- Revocation is now structural; offline lag is bounded by a signed absolute
  `grace_exp`.
- External input is treated as untrusted: webhook bodies are HMAC-gated before
  parsing, tokens are length- and structure-bounded, and no token or secret is
  logged.
